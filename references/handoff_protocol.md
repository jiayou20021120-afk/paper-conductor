# handoff 协议（阶段间产物交接）

跨 skill、跨会话最容易丢的就是上下文。每次从一个阶段进入下一个阶段，产出一个标准化的"交接包"，让下一个 skill（或下一个会话）零损耗接手。

## 交接包模板

```
## 交接包：阶段 N（X）→ 阶段 N+1（Y）

### 本阶段产物
- [产物 1]：路径或摘要
- [产物 2]：路径或摘要

### 下阶段需要的输入
- [输入 1]：从上面哪个产物来
- [输入 2]：...

### 尚未解决 / 需要决策
- [开放问题 1]
- [风险或假设]

### 不变量（不要在下阶段被改动）
- [比如：已核验的数据、已确定的 RQ、已锁定的术语表]
```

## 为什么要有"不变量"这一栏

下游 skill 容易顺手改上游已经定死的东西（改了 RQ、动了已核验的数据、换了术语）。把不变量显式列出来，等于给下一个 skill 立一道护栏。这一条尤其重要：**已核验的数据和文献绝不在下游被悄悄改写或编造。**

## 各交接点速查

| 交接 | 关键产物 | 关键不变量 |
|---|---|---|
| 1→2 选题 → 调研 | RQ + 假设 + 范围 | RQ 不在调研中被偷换 |
| 2→3 调研 → 写作 | 文献清单 + gap + 方法蓝图 | 文献条目、引用准确性 |
| 3→4 写作 → 制图 | 方法/架构章节文字 | 方法描述与正文一致 |
| 3→5 写作 → 润色 | 全文草稿 | 论点、数据、引用 |
| 4→5 制图 → 润色 | 图 + caption | 图文对应关系 |
| 5→6 润色 → 审稿 | 干净稿 | 语言改动不伤原意 |
| 6→3/5 审稿 → 修订 | 评审意见 + 修订路线 | 哪些是 must-fix vs 可争辩 |
| 6→7 审稿 → 答辩 | 定稿 | 核心贡献的表述 |
| 7 答辩 / 8 投稿 | 幻灯 / 投稿包 | 与论文事实一致 |

## 最多两轮修订

审稿 → 修订 的回路最多两轮。两轮后仍未解决的，写进"局限"（limitations），不要无限循环，也不要为了过审而编造或粉饰。

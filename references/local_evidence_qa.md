# 本地证据可回溯文献问答（Local Evidence-Grounded QA）

阶段 2（文献调研）的内置能力。**借鉴 paper-qa 的方法学，不借它的工程**：保留"逐块取证 + 逐句引用 + 证据不足拒答"的内核，丢掉向量索引、持久化嵌入、调用外部 embedding API 的工程外壳。引擎就是 Claude 自己，**不需要任何 API key**。

适用：用户有一组本地论文（PDF / docx / markdown），想就某个研究问题得到**有出处、可回溯、不编造**的回答，而不是一段读起来像综述但来源不明的文字。

## 依赖（都可选，缺了有降级路径）

- `markitdown`：把 PDF / docx / pptx 转 markdown。没有就让用户先转好，或只处理已有的文本文件。
- `fff` MCP / `grep`：语料大时做关键词召回。语料小时根本用不到。

## 五步协议

### ① 采集 Ingest
把目标文件夹里的源文件转成 markdown，落到一个工作目录（如 `<语料目录>/.evidence_cache/`）：

```
markitdown 某篇.pdf > .evidence_cache/某篇.md
```

分块：按标题 / 自然段切，每块记下 `来源 = 文件名§段号`（或页码）。这个定位串是后面引用可回溯的根。

### ② 检索 Retrieve —— **自适应,这是关键**

先估语料规模（分块总数）：

- **小语料（分块 ≲ 50，典型"一个 RQ 精读几篇"）→ 跳过检索,全读。**
  关键词检索唯一的软肋是同义改写漏召；语料小到能全读时，这个软肋直接消失，召回率 100%。**这是默认且推荐的路径。**
- **大语料（分块 ≫ 50）→ 才启用关键词召回。**
  从问题抽关键词，并**主动做同义 / 上下位扩展**（"披露" → "标注 / 标识 / disclosure / labeling"），用 fff/grep 召回候选块。扩展是为了补关键词匹配的天生短板，但仍不是零漏，要在产出里诚实标注"检索可能有遗漏"。

### ③ 取证 Evidence —— **RCS 内核，最重要的一步**

对**每个**候选块（小语料就是每一块），单独产出一条证据记录，**不要跳过直接合成答案**：

| 字段 | 说明 |
|---|---|
| 相关性摘要 | 这块和问题的关系，一两句 |
| 相关性打分 | 1–10。<4 视为无关，丢弃 |
| 精确引文 | 从原文**逐字**摘出的支撑句（不是转述） |
| 来源定位 | `文件名§段号` |

这一步是它比"直接让模型读完写答案"少幻觉的根本原因：先逼模型对每块表态、打分、摘原文，再谈合成。

### ④ 合成 Answer
**只用打分达标（默认 ≥6）的证据**合成答案：

- 每个论断后挂 `[文件名§段号]`，多来源就并列 `[A§3][B§7]`。
- **证据不足就明确拒答**："现有材料不足以回答 X，缺的是 Y。" 不外推、不拿常识补、不编引用。这条踩死红线，不可让步。
- 有冲突的证据要并陈，不要替用户和稀泥。

### ⑤ 产出 Output
默认输出三块，并**默认存成 markdown 文件**（`<语料目录>/evidence_qa_<问题摘要>.md`），方便回填论文：

1. **答案**（带逐句引用）
2. **证据表**：论断 → 源文件 → 引文 → 分数
3. **未覆盖**：问题里没被任何证据触及的部分 + 检索可能的遗漏

## 与升级路径的关系

这是 conductor **自己做**的能力，不替代外部 skill：

- 要系统性**网络**检索 + 来源验证 → `deep-research`
- 已有结构化 `.bib` 库做引用检索 → `bib-search-citation`
- 本协议专管"**本地已有的几篇全文**，要可回溯地问出东西"，三者互补不重叠。

## 常见坑

- **跳过 ③ 直接合成。** 那就退化成朴素 RAG / 直接问答，幻觉回来了。逐块取证是内核，不能省。
- **大语料硬走全读。** 会超上下文、变慢。过了阈值就老老实实上关键词召回，并标注遗漏风险。
- **把分数当真值。** 打分是排序和过滤工具，不是客观置信度。阈值（4/6）是手感，按语料质量调。
- **引文转述。** ④ 的引文必须逐字摘原文，一转述就失去可回溯性。

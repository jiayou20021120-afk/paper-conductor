# 语言终检：冷读协议（阶段 5 第④关）

定位：在 guard 过零、深修稿（`deep_revision_pass.md`）完成之后、交付之前的最后一道语言关。

来源：2026-07 一篇实证论文的完整教训。排印/词频双引擎全过、两轮带上下文的模型盲判也过，作者一句话仍抓出首句语病；按本协议补全流程后，三轮又抓出三十余处问题，其中包括一个地理常识错误和一处口径命名失实。工具全过从来不等于语言干净，这份协议把"剩下的那部分"变成可执行的步骤。

## 一、三层检测栈（机器部分）

1. **排印/词频层**：`scripts/ai_tell_guard.py` + aiwei-zh 硬门（破折号/引号/本文密度/口水词）。这是下限，不是终点。
2. **统计层**：句长 burstiness（CV 越低越像机器）、TTR 词汇丰富度、词汇集中度、段内三元并列硬约束。开源引擎：[aigc-humanizer-zh](https://github.com/shuohui-air-technology/aigc-humanizer-zh)（16 种模式正则 + L2 统计层，可独立运行，不需要 MCP）。
3. **表层打分与段句定位**：[academic-humanizer-zh](https://github.com/zkrun/academic-humanizer-zh)（S1-S9 脚本确定性打分，支持 .docx，自动跳过参考文献与表格，段句级定位）。

**铁律：打分器 ≠ 流程。** zkrun 的 rubric 明文规定：语义判读不限于表层高分段，节奏与口吻是文档级特征，表层 0% 的段也要通读评估。跑完三个引擎只是拿到客观下限，语义层还没开始。

## 二、语义层人工通读（C1-C3）

按 rubric 三项逐段判读，每项必须引出原文证据：

- **C1 节奏过平滑**：句句长而均衡、每段以工整总结收尾、无停顿插入转折。
- **C2 推理扁平**：无例外、无对比、无边界声明、无作者判断，像教科书摘要。
- **C3 口吻错位**：学科口吻被磨成通用学术腔，或口语混进学术语域。

C3 的高发形态清单（实抓样本）：

| 类型 | 例 | 改法 |
|---|---|---|
| 口语垫层混学术腔 | 说到底／接起来看／有意思的是／顺带一提／要紧／数值"走到"／资金"吸走" | 换学术语域动词或直接删垫层 |
| 直译式名词化 | "连接通过两项检验完成"／"把X放回全景" | 还原为主谓宾："两项检验将…联系起来" |
| 生造词 | "数字回归"／"行业史上的重排" | 用现成汉语词："重现""变动" |
| 受格与指代错位 | 许诺对象写错；"这两件事"先行词落空 | 逐句核对施受与先行词 |
| 冒号过密 | 一句双冒号；单段冒号≥3 | 拆句或改逗号 |
| 叠喻连用 | 门／跨线／分水岭一句三喻 | 一句最多一喻 |
| 拟人 | 证据"讲出什么" | 改为"据以判断" |

## 三、无触发全文冷读（人工，交付前必做）

**响应式修改不等于可交付。** 逐条回应审稿或反馈之后，必须再做一遍与任何触发无关的冷读：当作第一次读这篇稿，覆盖四类，每类独立过一遍：

1. **口吻语病**：按上表逐段扫。
2. **数字回脚本**：正文每个统计量与生成它的脚本输出逐个核对，零漂移。
3. **术语一致性**：同一概念全篇一个名；分组词（如"先发/后开放"）的成员在方法节定义与各处使用完全一致——分组成员写串是内部矛盾硬伤的高发点。
4. **事实性常识断言**：地理归类、历史年代、机构名称、平台机制这类陈述逐条过脑。"北欧四国"实为荷兰加爱尔兰加瑞丹挪这类错误，前三类检查全都抓不到，只有这一步能抓。

## 四、零上下文第三方冷读终审

带上下文的审读者（包括改稿者本人、参与过讨论的模型线程）都有锚定盲区：只顺着被点过的方向看。终审要交给一个不知道任何修改史的新读者（新会话或另一个模型），指令要点：当第一次读、只挑毛病、事实断言逐条过、正文数字互查内部一致性、找不到问题的类别明说而不硬凑。它的发现先独立核实再采纳。

实战中这一步抓出了口径命名失实（平台页面金额不等于实际到账）、分组自相矛盾、样本成功率与平台官方口径冲突从而暴露数据覆盖偏差——全部是前三步的幸存者。

## 五、完成度表述禁令

禁说"零遗漏／见底／完全解决／全部收口"。可以说的上限是"本轮清单已清"。宣布完成会让检查在触发点耗尽时停下，而不是在文稿真正干净时停下——这句禁令本身就是本协议最重要的一条。
